## 1. 产品定位

bowknot-workbench 是一个**本地优先的 AI 助理与多 Agent 协作工作台**。

它有三个核心特征：

1. **有形象的主 Agent**：内置一位“助理”，以虚拟形象与用户长期相处，能说话、表达情绪并执行动作。
2. **可扩展的多 Agent 协作**：用户可以创建不同人设的 Agent，单独对话，或把它们拉进群聊，由主 Agent 自动派发任务并汇总汇报。
3. **本地优先与插件化能力**：数据由本地服务持久化；插件作为 tool 合集按需安装，为 Agent 提供可调用的能力；Apps 与 AIGC 逐步接入。

首期不是云端多租户 SaaS，也不是传统业务管理系统。

## 2. 目标用户与场景

### 2.1 目标用户

- 希望把 AI 作为长期个人助理使用的用户
- 在意数据留在本地、可自行管理与备份的用户
- 愿意配置 Agent、人设与插件，以获得个性化能力的用户

### 2.2 典型场景

- 日常找主 Agent 聊天、倾诉、让助理记录提醒与偏好
- 为不同用途创建 Agent（写作、研究、代码、日程等），分别对话
- 把多个 Agent 拉进群聊，让主 Agent 拆解任务、分派执行并汇总结果
- 从本地或远程安装插件，为指定 Agent 开放对应工具
- 查看、修正或删除某个 Agent 的长期记忆
- 使用 AIGC 生成内容，并在工作台中继续加工

## 3. 核心概念与术语

| 术语 | 定义 |
| --- | --- |
| 主 Agent / 助理 | 系统内置且唯一的核心 Agent。负责与用户的日常对话、群聊中的任务派发与汇总，拥有虚拟形象 |
| 动态 Agent | 用户创建的 Agent。拥有独立人设、长期记忆与插件权限 |
| 人设 | Agent 的身份、语气、目标、行为边界等配置 |
| 单聊 | 用户与某一个 Agent 的一对一会话 |
| 群聊 | 用户、主 Agent 与若干动态 Agent 共同参与的会话；主 Agent 负责任务派发与最终汇报 |
| 会话 | 一次连续的对话上下文，分为单聊与群聊两种类型 |
| 长期记忆 | 跨会话保留的 Agent 记忆。每轮对话由 AI 判断是否写入，按 Agent 隔离 |
| 记忆索引 | 某个 Agent 的记忆总览，用于检索与管理 |
| 插件 | 能力的安装单元，包含一个或多个工具；可从本地或远程安装 |
| 工具 | Agent 可调用的具体能力，由插件提供 |
| Apps | 由 Agent 驱动的 Web 应用，具体形态后续细化 |
| 本地服务 | 工作台在本机运行的服务端，负责持久化、模型与语音接入、插件安装与运行 |

## 4. 信息架构

| 一级导航 | 路由（暂定） | 模块职责 | 首期状态 |
| --- | --- | --- | --- |
| 工作台 | `/workbench` | 统一入口、最近会话与快捷操作 | 暂缓，保留占位 |
| Apps | `/apps` | Agent 驱动的 Web 应用 | 后续 |
| 助手 | `/assistant` | 主 Agent 单聊；形象由全局悬浮卡片承载 | MVP |
| Agents | `/agents` | 动态 Agent 管理、单 Agent 对话、群聊 | MVP |
| AIGC | `/aigc` | 生成能力与作品管理 | MVP，待细化 |
| 插件 | `/plugins` | 插件安装、来源管理、工具清单与授权 | MVP，需新增导航 |

说明：

- 全局导航固定在工作台左侧，内容区在导航右侧展开；页面内面板不再为导航预留空间。
- 主 Agent 形象不属于任何页面，由 layout 全局层渲染为透明悬浮卡片；layout 顶部栏提供显示 / 隐藏按钮。
- 现有导航只有工作台、Apps、助手、Agents、AIGC，需要补充“插件”一级入口。
- 群聊不作为独立一级导航，入口与管理归入 Agents 模块；群聊会话本身在 Agents 内打开。
- 主 Agent 的日常对话在“助手”中；主 Agent 参与群聊时的表现与普通成员一致，但额外承担派发与汇总职责。

## 5. 核心流程

### 5.1 首次进入

1. 用户打开工作台，本地服务完成初始化
2. 以全局悬浮形象卡片展示主 Agent 与欢迎语
3. 引导用户完成基础设置：模型接入、语音开关、记忆开关
4. 进入助手页面开始对话；layout 顶部栏按钮可随时隐藏或显示形象

### 5.2 与主 Agent 对话

1. 用户在助手页输入文字，或在任意页面按住 `Ctrl + Space` 发起全局语音对话
2. 主 Agent 以流式方式回复；全局悬浮形象同步进入“聆听 / 思考 / 说话”等状态
3. 回复过程中可触发情绪或动作表现
4. 全局语音的结果只做语音播报，文字记录写入当前会话
5. 系统判断本轮是否产生长期记忆并写入
6. 会话与记忆由本地服务持久化

### 5.3 创建动态 Agent

1. 在 Agents 模块新建 Agent
2. 配置名称、人设、模型与插件权限
3. 保存后可进入单聊
4. 该 Agent 的会话与记忆独立保存

### 5.4 群聊任务

1. 用户选择若干 Agent 创建群聊，主 Agent 默认在群内
2. 用户发出需求
3. 主 Agent 拆解任务并派发给合适的 Agent
4. 各 Agent 执行并返回结果
5. 主 Agent 汇总结果并向用户汇报
6. 全过程消息与任务结果留在群聊中，可回看

### 5.5 记忆沉淀与管理

1. 每轮对话结束后，由 AI 判断是否写入长期记忆
2. 记忆按 Agent 隔离，采用“一个记忆索引 + 每周一个记忆文件”的存储方式
3. 用户可在记忆管理界面查看、编辑、删除某个 Agent 的记忆
4. 记忆在后续对话中按需检索并注入上下文

### 5.6 插件安装与授权

1. 用户从本地或远程来源安装插件
2. 插件安装后展示其包含的工具清单
3. 用户在 Agent 配置中选择该 Agent 可使用的插件范围
4. Agent 在对话或任务中调用已授权的工具
5. 工具调用过程对用户可见，结果回到会话中

## 6. 跨模块约定

### 6.1 前端先行

- 首期以页面与交互实现为主，先完成 UI，再按前端实际调用收敛后端接口
- PRD 描述用户可见行为与数据语义，不提前绑定后端实现细节
- 页面按“一次一个页面”推进，每个页面完成后再进入下一个

### 6.2 本地数据

- 数据由本地服务持久化，本地优先，不默认上传云端
- 需要明确可备份、可迁移的数据边界
- 长期记忆采用文件存储：每个 Agent 一个记忆索引，按周拆分记忆文件
- 建议目录结构（待实现确认）：
  - `memories/{agentId}/index.json`
  - `memories/{agentId}/YYYY-Www.md`

### 6.3 会话模型

- 会话分为单聊与群聊两种类型
- 单聊参与者为用户与一个 Agent
- 群聊参与者为用户、主 Agent 与一个或多个动态 Agent
- 会话需要保存消息、参与者、任务状态与产出

### 6.4 全局形象与状态机

主 Agent 形象由 layout 全局层渲染为**纯透明、可拖拽的悬浮卡片**，在工作台所有页面常驻：

- layout 顶部栏提供唯一的显示 / 隐藏按钮，状态跨页面保持
- 卡片只承载形象与状态，不显示消息、转写文字或输入框
- 支持拖拽、边缘吸附、位置记忆与复位
- 层级高于页面内容，低于弹窗、抽屉与全局提示，且不得遮挡顶部栏与左侧导航
- 卡片隐藏时，全局语音输入仍可用
- 全局语音快捷键为按住 `Ctrl + Space`，在工作台任意页面生效；结果只做语音播报，文字记录写入当前会话

形象渲染技术路线暂未定（3D VRM 或视频渲染），PRD 先定义与渲染无关的语义状态：

| 状态 | 触发 |
| --- | --- |
| 待机 | 无对话、无任务 |
| 聆听 | 用户输入中或语音输入中 |
| 思考 | 模型生成中 |
| 说话 | 回复播报中 |
| 情绪 | 回复内容触发喜、怒、哀、惊等情绪 |
| 动作 | 回复内容或用户指令触发挥手、跳舞等动作 |

具体优先级、打断规则与动作资源在 [01-assistant.md](./01-assistant.md) 中细化。

### 6.5 Agent 能力边界

每个 Agent（含主 Agent）具备：

- 人设
- 长期记忆
- 可使用的插件 / 工具范围

动态 Agent 与主 Agent 共用同一套能力模型，差异在于主 Agent 内置、不可删除，并承担群聊派发与汇总职责。

### 6.6 权限与安全

- 插件安装需要用户确认来源
- Agent 只能调用被授权的工具
- 工具调用、任务派发与记忆写入应可追溯
- 本地数据不应在未经用户同意的情况下离开本机

### 6.7 交互与视觉

- 沿用现有 antdv-next + unocss 体系，不另起一套视觉语言
- 支持明暗主题，沿用现有主题切换方式
- 统一使用现有的布局容器、图标与间距规范
- 每个页面单独设计，先结构后视觉，避免一次性铺开

### 6.8 状态与异常

- 所有列表与详情页需要定义加载、空状态与错误状态
- 流式回复需要支持中断与重试
- 插件、模型、语音等服务不可用时，需要给出可操作的提示，而不是静默失败

## 7. 首期范围

### 7.1 纳入首期

- 助手：全局悬浮形象卡片、单聊、全局语音输入、语音播报、情绪与动作状态
- Agents：Agent 列表与创建、人设配置、插件权限、单 Agent 对话、群聊与任务派发汇总
- 插件：插件安装、来源管理、工具清单、按 Agent 授权
- 长期记忆：自动写入判断、文件存储、记忆管理与编辑
- AIGC：首期保留入口与基础能力，具体范围在模块 PRD 中确定

### 7.2 暂不纳入首期

- 工作台首页的完整信息聚合
- Apps 的完整应用形态与运行机制
- 多用户、账号体系与云端同步
- 插件市场、评分与分发体系

## 8. 开放问题

| 问题 | 影响 | 处理时机 |
| --- | --- | --- |
| 形象的渲染路线：3D VRM 还是视频渲染 | 全局悬浮卡片的性能与资源占用 | 形象模块技术选型时确定 |
| `Ctrl + Space` 与输入法 / 浏览器快捷键冲突 | 全局语音的可用性 | 联调时确认，必要时允许自定义 |
| 全局语音写入哪个会话 | 对话归属与用户预期 | 默认最近会话，确认后固化 |
| 语音链路：TTS / ASR 的本地或云端方案 | 语音播报与语音输入的体验和成本 | 助手模块 PRD 细化时确定 |
| 模型接入方式与多模型切换 | Agent 配置、对话与费用 | 助手 / Agents 模块 PRD 细化时确定 |
| AIGC 的具体能力与作品管理 | AIGC 模块范围 | AIGC 模块 PRD |
| Apps 的运行形态与 Agent 驱动方式 | Apps 模块范围 | Apps 模块 PRD |
| 记忆容量、检索方式与冲突处理 | 记忆体验与性能 | 记忆模块 PRD |
| 插件运行时与安全边界 | 插件安装、调用与权限 | 插件模块 PRD |
| 是否需要登录与多用户 | 导航、数据隔离与权限 | 首期按单用户本地使用设计 |
