# Bowknot Workbench 产品总览

> 本地优先的 AI 助理与多 Agent 协作工作台，基于 [mygo](https://github.com/egoist/mygo) 的原生 Go 桌面应用。  
> 最后更新：2026-11-24  
> 本文是产品定位、功能范围与实现状态的唯一总纲；编码约定与质量要求见 [AGENTS.md](../AGENTS.md)。

## 1. 产品定位与最终效果

Bowknot 把「一个贴身助理」和「一支可组建的员工团队」放进同一个桌面工作台：主助手负责对话、记忆与调度，员工 Agent 负责专业任务，任务系统负责把一次委派变成可追踪、可汇报、可审计的交付过程。

所有会话、任务、记忆与产物都保存在本机。核心界面是立即模式原生 UI，只有安装的第三方应用在独立沙箱 WebView 中运行。

### 1.1 最终要实现的效果

1. **一个随时可用的主助手**：有独立人设、长期记忆和稳定形象，能日常对话、理解交付物、记住用户偏好，并在需要时把事情派给合适的员工。
2. **一支可组建的员工团队**：用户按角色创建员工，每位员工有人设、模型、工具授权和独立记忆；可以单独直聊，也可以拉群协作。
3. **可靠的任务闭环**：主助手一句话派活，员工后台排队执行，完成后主助手主动向用户汇报；失败、超时、取消、重试都有明确状态与审计记录。
4. **可积累的工作资产**：Agent 的交付物统一落在本地工作区，能在文件库中查找、预览、用系统应用打开，并与消息、任务、员工关联。
5. **越用越懂人的记忆**：模型主动抽取原子事实，按作用域隔离、去重、纠正与检索注入；用户可以查看、关闭、清空，敏感信息不落库。
6. **可扩展的应用与插件生态**：应用提供独立界面，插件提供模型可调用的工具；安装、授权、工具开关、数据清理都有清晰边界。
7. **常驻桌面的陪伴形态**：桌宠独立常驻、可拖动吸附、点击闲聊与语音播报，后续补到点提醒，让助理从窗口里走出来。

### 1.2 明确的非目标

- 不做云端同步、多设备协同与云备份；数据默认只在本机。
- 核心界面不内嵌 WebView；只有第三方应用使用沙箱 WebView。
- 首版记忆不做向量数据库与 embedding 检索，优先关键词与摘要。
- 不做通用低代码平台或任意脚本执行环境；扩展能力收敛到应用与插件包。
- 不以 macOS / Linux 为首发验证平台，当前以 Windows 为主。

## 2. 已确认的关键决策

这些决策已经落到实现中，后续改动需要先重新评估，避免破坏现有契约。

| # | 决策 |
| --- | --- |
| 1 | 本地优先：数据根目录为 `~/.bowknot-workbench`，可用 `BOWKNOT_HOME` 覆盖。 |
| 2 | 核心 UI 为原生立即模式；第三方应用运行在 Untrusted 沙箱 WebView，插件以 native 子进程执行。 |
| 3 | 主助手是唯一默认对外发言人；员工只对任务负责，结果回给派单人，不能越过主助手直接联系用户。 |
| 4 | 用户可以直接与员工直聊；跨 Agent 协作只发生在群聊内，不开放 Agent 私聊。 |
| 5 | 任务是一等对象：任务与任务线程 1:1，终态幂等，重启后未完成任务收敛为失败，不补发汇报。 |
| 6 | 记忆只存原子事实，不存整段对话；`user` / `agent` 双作用域，关键词检索与周期摘要优先。 |
| 7 | 产物只允许通过 `builtin_save_artifact` 写入；产物不可变，路径限制在工作区内，HTML 只展示源码不内嵌渲染。 |
| 8 | 工具调用必须经过注册表、授权校验、危险审批与审计；审批缺失时危险工具一律拒绝。 |
| 9 | 配置分层：`config.json` 放启动依赖、模型服务与密钥；`app_meta` 的 `settings.v1` 放运行参数；人设与授权留在实体表。 |
| 10 | 密钥只写不读，界面、日志、错误与契约返回值只出现脱敏值；模型配置重启生效，运行参数保存即生效。 |
| 11 | SQLite 单库、单连接 + WAL；`database/sql` 只出现在 `internal/store`，升级 schema 只新增迁移文件。 |
| 12 | 包升级保留当前版本与上一个版本；卸载默认删除整个包目录，`keepData` 时保留 `data/`。 |

### 3.2 核心协作

#### 主助手对话（已完成）

- 多轮流式回复、停止生成、重答、复制、删除消息；Markdown 正文渲染。
- 解析并展示 `reasoning_content` 思维链，随消息落库，重启后可回看。
- 思考与工具调用按发生顺序内联展示、可折叠，刷新后保留完整记录。
- 危险工具执行前弹窗确认，工具结果与状态（执行中/成功/失败/拒绝）可见。
- 会话置顶、重命名、删除；消息分页加载，首屏只取最近一页。
- 模型选择器；发送任务后渲染任务卡片，可查看过程、取消或重试。
- 助手页可打开员工的直聊会话，汇报消息带任务与产物摘要。

边界：跨会话搜索与导出未做；多模态输入见 3.6，群聊暂不支持附件。

#### 员工 Agents（已完成）

- 创建与编辑员工人设：名称、性别、年龄、性格、职责、对用户的称呼与补充说明。
- 每位员工有独立会话、独立模型、独立记忆与插件授权。
- 任务线程是内部工作记录：用户只读查看，不提供输入框；直聊是独立通道。
- 员工页可直接查看任务线程、产物与记忆面板。
- 员工可被拉入群聊，作为群成员参与讨论。

边界：员工不能主动联系用户，也不能与其他员工私聊；所有对外表达都经主助手或群聊。

#### 群聊协作（已完成）

- 主助手固定为群主，负责编排、@ 成员与最终汇总。
- 支持用户直接 @ 成员，也支持主助手或成员在回复中继续 @ 其他成员，兼容全角 `＠`。
- 单条用户消息最多触发配置上限内的成员讨论轮次（默认 3 轮），每名成员每轮发言一次，最后由群主收尾。
- 群成员消息带发送者姓名与头像；群聊状态通过 revision 轮询刷新，流式内容节流更新。
- 群内派发的任务沿用同一任务模型，汇报写回群聊来源会话。

边界：群聊单条消息不提供「重答」，因为会丢失 @ 编排上下文。

#### 任务系统（已完成）

- 状态机：`queued → running → done / failed / canceled / timeout`，失败与终态可重试。
- 每位员工一个 FIFO 队列，后台任务并发度为 1；全局并发上限默认 4。
- 任务超时、最大尝试次数、指数退避与自动重试均可配置；只对限流、超时、网络等临时错误自动重试。
- 状态迁移使用条件更新，保证取消与完成竞争时终态只写一次；终态汇报用 `reported_at` 去重。
- 应用重启后未完成任务收敛为失败，可手动重试，不自动补跑、不补发汇报。
- 任务页提供总量、成功率、平均耗时、状态/员工/时间范围筛选、标题与描述搜索、过程详情与员工表现。
- 任务结束会为负责员工写入一条记忆快照，并把产物挂到任务下聚合展示。

#### 工具调用与审批（已完成）

- 模型请求可声明工具；对话循环执行「请求 → 授权校验 → 危险审批 → 执行 → 结果回填 → 继续生成」。
- 单次生成内工具调用轮数上限可配置（默认 5），避免死循环。
- 工具调用与结果持久化到 `tool_call` 表，重启后仍可展示。
- 内置工具覆盖：人设、员工派发与任务查询/取消、产物保存、记忆增删改查、工作区文件读写与检索。
- 应用工具按全局开关启用；插件工具按 Agent 授权；执行外壳负责超时、输出上限、panic 捕获与审计日志。
- 插件工具通过 native 子进程执行，安装/卸载/升级前会停止对应进程，避免 Windows 文件占用。

边界：插件声明的 `fs` / `net` / `host` 权限目前只保存，不在运行时强制；Bun 运行时尚未接入。

### 3.3 知识与产出

#### 长期记忆（已完成，增强待做）

- 回复完成后由模型异步抽取原子记忆，每轮限量；停止或失败的消息不抽取。
- 记忆按 `user` / `agent` 作用域隔离，支持 `profile` / `preference` / `fact` / `decision` / `event` 类型。
- 内容规范化后哈希去重；用户纠正旧信息时旧记忆标记为 `superseded`，不再注入。
- 注入策略：置顶、最近时间窗口、关键词命中，按优先级合并去重并受条数与字符预算限制。
- 周期摘要按周聚合原子记忆，用于「上次」「之前」这类回溯检索；摘要失败保留 `dirty`，后续重建。
- 记忆工具支持记住、检索、更新、遗忘；全局与单个 Agent 均有开关，敏感信息在抽取前过滤。
- 记忆面板可查看当前作用域的记忆并整体清空；消息上展示「已记住」标记。

边界：记忆的增删改由模型工具完成，界面只支持查看、开关与清空；语义/向量检索、月摘要与更细的冲突消解尚未实现。

#### 文件库与产物（已完成，增强待做）

- 所有 Agent 产出统一落在工作区 `~/.bowknot-workbench/workspace`，托管文件在 `workspace/artifacts/`。
- 支持 Markdown、文本、代码、图片、链接、HTML 源码与通用文件兜底类型。
- `builtin_save_artifact` 是唯一写入入口：校验文件名、扩展名、大小、链接协议与来源路径，先写临时文件再原子重命名。
- 产物自动关联会话、任务与消息；任务汇报消息按任务 ID 带出产物。
- 支持 Markdown/代码/图片/文本原生预览；HTML 只展示源码并用浏览器打开；其余类型交给系统应用。
- 文件库一级页面支持按类型、来源员工筛选、搜索、预览、删除与在文件夹中显示。
- 消息、任务详情、右侧预览 Drawer 与文件库共享同一套产物组件。

边界：产物不可变，修改等于新建；版本化、差异对比、缩略图、孤儿文件清理尚未实现。

#### 工作区文件工具（已完成）

- 内置列目录、建目录、读文件、写文件、精确编辑、删除、glob 与内容搜索。
- 所有路径限制在工作区内，拒绝越界路径与符号链接逃逸。
- 通过工作区写入的文件会同时登记到文件库，用户无需额外整理。

### 3.4 扩展与配置

#### 应用管理（已完成）

- 支持本地目录、本地 tar 与远程 tar 安装，安装前可预览 manifest 与能力清单。
- manifest 校验、tar slip 防护、下载体积上限、原子安装/回滚、升级保留上一版本。
- 支持卸载（保留或删除应用数据）、工具开关、清空数据、最近使用记录与数据大小统计。
- 应用在独立窗口运行：原生标题栏 + Untrusted 沙箱 WebView，通过 `bowknot-app` 协议提供静态文件，未注册应用直接 404。
- 内置示例应用与网页搜索插件在首次启动时自动安装。

边界：没有应用市场、远程源签名校验与统一升级策略；远程包目前只支持可选 SHA-256 校验。

#### 插件管理（已完成）

- 支持本地/远程 tar 安装、预览、卸载与按 Agent 授权；工具注册表随安装、卸载、授权变化同步。
- 插件 manifest 支持工具声明、参数 schema、危险标记、超时与 permissions 字段。
- native 插件通过 stdio JSON-RPC 子进程执行，带空闲超时与生命周期管理；执行前校验 Agent 授权。

边界：Bun 插件运行时未接入；permissions 未在运行时强制；卸载没有 `keepData` 选项，当前默认删除插件数据。

#### 模型服务（已完成）

- 多服务商：名称、类型、BaseURL、API Key（只写不读、脱敏展示）、启用开关与连接测试。
- 多模型：从服务商拉取或手动添加，可设默认模型；内部 key 为 `providerId/modelId`。
- 模型元信息：是否支持图片理解、上下文长度、最大输出长度，供设置页展示。
- 网关按模型 key 路由，未命中时返回中文错误，不静默回退；没有配置时回退 Fake 网关保证首次启动可用。

边界：图片理解、上下文长度与最大输出长度目前只存储与展示，尚未影响聊天行为。

#### 设置中心（已完成）

- 分类：模型服务、语音合成、对话与提示词、任务调度、群聊与工具、记忆、外观、数据与日志、关于。
- 运行参数写入 `settings.v1`，保存即生效；模型配置与日志级别标注重启生效。
- 全局提示词追加到主助手、员工与群主的系统提示词。
- 明暗主题与跟随系统可切换并持久化；标题栏与设置页保持同步。
- 数据页展示数据目录、占用与日志级别；备份、恢复与清理按钮仍是占位。

### 3.5 桌面形态

#### 桌宠（部分完成）

- 已实现：`pet.json` 解析与校验、图集加载、透明无边框置顶窗口、形状级鼠标穿透、拖动与点击判定、边缘吸附、位置持久化。
- 已实现：单击播放动作并按配置调用语音合成；非循环动作播完回到 idle；主窗口关闭隐藏到托盘，托盘可显示/隐藏桌宠与退出。
- 素材：官方形象用 `go:embed` 打进二进制；`idle` 为正式图集，`talk` / `click` 仍为临时验证素材，序列帧片段库仍在制作。
- 未完成：提醒（P5 未开始）、完整片段库与内部状态机（P6 进行中）、启用开关/缩放/置顶/音量/静音/免打扰/试听等设置项。
- 未接入：点击闲聊目前播放固定短句，没有走主助手生成；任务完成也没有播报。

#### 语音合成（已完成）

- 豆包语音合成 2.0（`seed-tts-2.0`）HTTP 接口，请求 PCM 后本地补 WAV 头播放，不引入额外解码依赖。
- 设置页提供语音合成配置；保存后下一次点击桌宠生效；未配置 API Key 时只做动作不发声。
- 串行播放，新播报打断旧播报；文本超长截断。

边界：目前只支持豆包，音色、音量、语速等高级参数未在界面暴露。

#### 提醒（未开始）

- 计划支持一次性与周期性提醒，到点触发桌宠动作与语音播报。
- 需要新增 `reminder` 表、调度器、免打扰时段与设置项；当前没有相关代码。

### 3.6 规划中

#### 工作台（占位）

- 一级导航已有「工作台」入口，但没有原生页面，访问时显示「该页面建设中」。
- 应用默认落地页仍为 Apps；工作台的聚合内容与快捷操作尚未定义。

#### AIGC 创作中心（占位）

- 左侧菜单已列出：生成中心、素材管理、角色管理、剧本创作、无限画布、提示词库、动作库。
- 右侧统一为占位；没有 contract、后端服务与真实生成能力。

#### 多模态输入（部分完成）

- 主助手对话与员工直聊的输入区支持选择或粘贴图片/文件（剪贴板截图直接转成附件），单条最多 4 个附件；图片单张 ≤ 5MB，其他文件 ≤ 20MB。
- 附件复用产物体系落盘：与 Agent 产物同表，自动出现在文件库、会话文件与消息附件区，可预览、删除。
- 图片以 data URL 作为 OpenAI 兼容 `image_url` 分段下发，MIME 由写入时探测；模型未勾选「支持图片理解」时直接拒绝，历史图片降级为文字提示。
- 图片重发范围为最近两条带图用户消息，单次请求最多 4 张；文本/代码附件仅在本轮内联 16KB，历史轮只给文件名。
- 消息气泡内展示图片缩略图（点击打开产物预览）与文件条；只有附件没有文字的消息也可以发送，会话标题回落到附件名。
- 模型配置的「最大输出长度」已作为 `max_tokens` 下发；删除用户消息会连带删除其附件记录与文件。

边界：群聊与任务线程不支持附件（入口隐藏且服务端拒绝）；上下文长度尚未转化为裁剪预算；PDF、Office 等二进制附件只登记不解析。

#### 消息搜索与导出（未开始）

- 会话内已支持分页，但没有跨会话全文搜索、消息筛选或会话导出。
- 后续优先评估 FTS5 `trigram` 分词，而不是直接依赖 SQLite 默认分词器。

#### 跨平台与自动更新（未开始）

- 当前以 Windows 为主要验证平台；macOS/Linux 适配与自动更新尚未开始。

## 4. 运行与数据

### 4.1 数据目录

默认位置为 `%USERPROFILE%\.bowknot-workbench\`，可用环境变量 `BOWKNOT_HOME` 重定向。

```text
.bowknot-workbench/
├── bowknot.db              # SQLite 主库：会话、消息、Agent、任务、记忆、产物、安装记录等
├── bowknot.db-wal          # WAL 文件，备份前应确保应用已退出
├── config.json             # 模型服务、密钥、语音合成等启动配置（勿外发）
├── apps/<id>/<version>/    # 应用包内容（当前版本 + 上一版本）
├── apps/<id>/data/         # 应用数据目录
├── plugins/<id>/<version>/ # 插件包内容
├── plugins/<id>/data/      # 插件数据目录
├── workspace/              # Agent 工作区，所有文件读写限制在此目录
│   └── artifacts/          # 托管产物文件：Agent 产物与用户上传的聊天附件
├── tmp/                    # 安装暂存与下载，启动时自动清空
└── logs/
    ├── app.log             # 当前日志，超过 10MB 自动轮转
    └── app-<时间戳>.log    # 轮转留档，最多保留 5 份
```

运行设置（任务并发/超时/重试、群聊与工具轮次、记忆参数、外观主题、全局提示词、桌宠位置）以单键 `settings.v1` 存放在 `bowknot.db` 的 `app_meta` 表；模型服务与密钥仍只写在 `config.json`。

### 4.2 备份与恢复

1. **先退出应用**。WAL 模式下直接复制运行中的 `bowknot.db` 可能得到不一致快照。
2. 备份三类内容即可完整还原：
   - `bowknot.db`
   - `config.json`
   - `apps/`、`plugins/` 与 `workspace/` 整目录
3. 日志与 `tmp/` 不需要备份。
4. 恢复：应用退出状态下，把上述文件与目录放回原位后启动；迁移机制会按需补齐 schema。

### 4.3 常见故障

| 现象 | 处理方式 |
| --- | --- |
| 启动报「打开数据存储失败」且错误包含 `database disk image is malformed` | 数据库损坏。退出应用后把 `bowknot.db` 改名为 `bowknot.db.broken-<日期>` 留证，重启会重建空库；需要旧数据时可用 `sqlite3 ".recover"` 导出后人工挑选。 |
| 启动报「database schema version N is newer than supported M」 | 数据库由更高版本程序写入。不要用旧程序强行打开，升级到对应版本即可。 |
| 会话/消息丢失但应用能启动 | 查看 `logs/` 是否有异常退出记录；消息落库有节流，异常退出时最后约 100ms 的流式内容可能丢失，属预期行为。 |
| 应用/插件列表存在但目录缺失 | 手工误删包目录所致。在页面上卸载（不保留数据）后重装即可。 |
| `tmp/` 有残留目录 | 无需处理，下次启动自动清理；也可手动删除。 |
| 桌宠或托盘异常 | 托盘创建失败时会降级为普通窗口，不阻塞启动；桌宠位置记录失效时回落到主屏右下角。 |

## 5. 质量校验

```bash
gofmt -l .
go vet ./...
go build ./...
go test ./...
```

- 提交前至少执行 `gofmt` 与 `go vet`。
- `go test -race` 在当前 Windows 纯 Go 环境可能因缺少 CGO 无法执行，需要在支持 CGO 的 CI 环境补跑。
- 窗口交互、渲染效果、安装动画、审批弹窗、托盘与桌宠行为不做自动化验收，由人工运行 `go tool mygo dev` 确认。

### 6.2 技术决策

| 事项 | 当前状态 | 需要决定 | 建议 |
| --- | --- | --- | --- |
