# 数据目录备份与损坏恢复说明

## 数据目录布局

默认位置为 `%USERPROFILE%\.bowknot-workbench\`，可通过环境变量 `BOWKNOT_HOME` 重定向。

```text
.bowknot-workbench/
├── bowknot.db        # SQLite 主库：会话、消息、Agent、应用/插件记录、授权、审计
├── bowknot.db-wal    # SQLite WAL 短暂存在，备份前应确保应用已退出
├── config.json       # 用户配置，含模型密钥（勿外发）
├── apps/<id>/<version>/   # 应用包内容（当前版本 + 上一版本）
├── apps/<id>/data/        # 应用数据目录（卸载时可选保留）
├── plugins/<id>/<version>/  # 插件包内容，布局同 apps
├── plugins/<id>/data/       # 插件数据目录
├── tmp/               # 安装暂存与下载，启动时自动清空
└── logs/
    ├── app.log        # 当前日志，超过 10MB 自动轮转
    └── app-<时间戳>.log  # 轮转留档，最多保留 5 份
```

应用内「设置 → 数据与日志」可以查看上述目录、当前占用与日志级别；「打开数据目录」「导出备份」目前是占位入口，尚未实现。

运行设置（任务并发/超时/重试、群聊与工具轮次、记忆参数、外观主题、全局提示词）以单键 `settings.v1` 存放在 `bowknot.db` 的 `app_meta` 表；模型服务与密钥仍只写在 `config.json`。

## 备份步骤

1. **先退出应用**。WAL 模式下直接复制运行中的 `bowknot.db` 可能得到不一致快照。
2. 备份三类内容即可完整还原：
   - `bowknot.db`（会话与安装记录）
   - `config.json`（配置与密钥）
   - `apps/` 与 `plugins/` 整目录（包内容与数据目录）
3. 日志与 `tmp/` 不需要备份。
4. 恢复：应用退出状态下，把上述文件与目录放回原位后启动即可；迁移机制会按需补齐 schema。

## 损坏恢复

| 现象 | 处理方式 |
| --- | --- |
| 启动报「打开数据存储失败」且错误包含 `database disk image is malformed` | 数据库已损坏。退出应用后把 `bowknot.db` 改名为 `bowknot.db.broken-<日期>` 留证，重启应用会重建空库；如需要旧会话，可尝试 `sqlite3 bowknot.db ".recover"` 导出后人工挑选。 |
| 启动报「database schema version N is newer than supported M」 | 数据库由更高版本程序写入。不要用旧程序强行打开，升级到对应版本即可。 |
| 会话/消息丢失但应用能启动 | 检查 `logs/` 中是否有异常退出记录；消息落库节流间隔为 100ms，最后一段流式输出在异常退出时最多丢失 100ms 的内容，属预期行为。 |
| 应用/插件列表存在但目录缺失 | 手工误删包目录所致。在页面上卸载（不保留数据）后重装即可。 |
| `tmp/` 有残留目录 | 无需处理，下次启动自动清理；也可手动删除。 |

## 设计约定

- 数据库写入统一经 `internal/store`，单连接 + WAL；升级 schema 只允许新增迁移文件，禁止改历史迁移。
- 升级安装保留当前版本与上一个版本目录，更早版本在安装后与下次启动时清理。
- 卸载默认删除整个包目录；`keepData=true` 只删版本目录、保留 `data/`，供重装续用。
- 日志轮转与临时目录清理均为尽力而为，失败只记日志，不阻塞启动。
